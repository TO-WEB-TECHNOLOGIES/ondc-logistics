# IGM: outbound /issue rewritten to IGM MVP v1.0.0

**Date:** 2026-10-09
**Type:** fix

## What changed

- Outbound `/issue` is built strictly in the IGM MVP v1.0.0 Scenario 1 shape:
  - **Create:** `category`, `sub_category`, `complainant_info`, `order_details`, `description`
    (images as URL strings), `source`, expected response/resolution times, `status`,
    `issue_type`, `issue_actions.complainant_actions`.
  - **Close (5a):** `status: CLOSED`, complainant history plus `CLOSE`, optional `rating`.
  - **Escalate (5b):** `status: OPEN`, `issue_type: GRIEVANCE`, history plus `ESCALATE`.
  - All 2.0 attributes (`refs`, `actors`, `descriptor`, `actions`, `level`, `source_id`,
    `complainant_id`, `last_action_id`, `resolution_id`) are gone. `/issue_status` is unchanged.
- Categories: added `igmCategory` and `subCategoryV1` (ITM01–ITM05, FLM04). `ITEM_WRONGLY_RETURNED`
  and `DELIVERY_DELAY` are rejected (400) and hidden until a 1.0 code is confirmed.
- App API:
  - Create: `images` takes URL strings (`{url}` objects are still accepted), `media` is
    removed, and `items` is only required for item categories.
  - Update: `action_code` is `CLOSE` | `ESCALATE` with optional `rating` (CLOSE only) and
    `short_desc`. `resolution_id`, `RESOLUTION_*`, `INFO_PROVIDED`, `OPEN`, `ESCALATED` and
    `CLOSED` are removed.
  - Update rules: no action on a CLOSED issue; ESCALATE only after a respondent RESOLVED;
    pre-1.0 issues return 409.
- Persistence:
  - Our complainant actions are stored as `complainant-<n>` (side `complainant`, with
    `updated_by` details), matching how echoed actions are keyed.
  - `order_details` is stored as `issue_refs`; `complainant_info` as an `issue_actors`
    COMPLAINANT row.
  - `resolution_provider` from `/on_issue` and `/on_issue_status` is stored as `issue_actors`
    rows (`resolution-provider`, `resolution-support`, `gro-<n>`) plus the new
    `issues.resolution_support_chat_link`. The new `issues.rating` holds the close rating.
- `GET /logistics/issues/:issueId`:
  - Renamed `descriptorCode`/`level` to `subCategory`/`issueType` and dropped `lastActionId`.
  - Added `respondentStatus`, `rating` and `resolutionProvider`.
  - The order-issues list was renamed the same way.
- Flow `ondc-baseline-igm`: create uses string `images`, no `media`, and the confirmed item id
  with quantity 1. Close sends `CLOSE` + `THUMBS-UP`. `runSearchInitConfirm` now also returns
  `itemId`.
- Docs: `docs/integration/igm.md` rewritten. The `ondc-api-contract` skill's IGM context note
  was corrected.

## Why

ONDC reviewer iteration 2: "Payloads are incorrectly sent… combined some attributes from IGM
version 1.0.0 & 2.0.0. Please refer this IGM doc (Scenario 1)."
